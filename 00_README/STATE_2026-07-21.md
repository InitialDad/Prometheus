### 0 of 167 models are verified usable

This is the important number. The 70 named Tenchu character OBJs
(`Rikimaru.obj`, `Ayame.obj`, `Lord_Gohda.obj` …) are **face + hands fragments**,
not characters. Evidence:

* `Rikimaru.obj`, `Ayame.obj` and `Rikimaru_Cinematic.obj` share an **identical
  bounding box to one decimal place** (X −13.2..5.9, Y −91.3..90.2,
  Z −169.9..−135.2) despite different vertex counts. Distinct characters cannot.
* The parsed skeleton places **arms at ±77 X**; the mesh spans only **−13..+6 X**.
  The geometry never reaches the arms.
* Each model shows 2 large vertical gaps — the face + 2 hands clustering already
  described in `00_README/RIKIMARU_BODY_FINDING.md`.

**The VIF-batch body geometry is still undecoded.** Any plan that treats

## 5. The port (Way of the Samurai, SLUS-20407)

Runs its main loop, **+2,803 frames** in the best drive (`FRAMES_ADVANCING`),
no bad dispatches, no bad allocations. **But the screen is a flat clear colour.**

What is measured, not assumed:

* **CPU translation is not the blocker.** 2,820 functions cover 82.6% of the
  1,198,208-byte PT_LOAD; every Ghidra symbol was translated and every
  translated TU is registered (131,608 entry addresses).
* **Texture uploads DO reach VRAM** — `[p4:gs-trx]` shows a 512×512 PSMT4HH
  transfer, a 256×128, and several 8×2 CLUT loads, all `dir=0` (host→local).
* 96 `TEX0` writes and 96 `prim=6` (SPRITE) kicks occur.
* Vblank is healthy (`[p4:vbl]` ticking; INTC_STAT bit 2 raised each frame).

So the defect is **downstream of upload**: rasterisation, sampling, or the draw
target. A `[p4:gs-sprite]` diagnostic was added logging FRAME/SCISSOR/TEST/TEX0
and vertex coords per kick, to separate three candidates — sprite *rejected*
(scissor/alpha/z), drawn *offscreen* (bad coords), or drawn into a buffer that
is *never displayed* (`FRAME.fbp` ≠ DISPFB).

### Claims withdrawn this session

* mods.db **191** ("gzmfs read overwrites live code") — **wrong**, corrected by
  192. `0x21D808` decodes **0.0%** as MIPS; it is data.
* "Only 9,784 bytes of the image are untranslated code" — **withdrawn**. The
  >92%-decode heuristic misclassifies: the ELF entry point (known code) scores
  only 54.7% over a 256-byte window.
* "No texture uploads happen" — **wrong**. It came from grepping logs for
  `TRXDIR`, which only ever appears as a `case` label and was never printed.
