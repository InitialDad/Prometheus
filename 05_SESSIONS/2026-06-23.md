# Session 2026-06-23

## Day 0 — Rikimaru fix shipped

**Root-cause analysis:**
1. Old exporter read `CHARA_ayame.bin` — a modded variant. Canonical archive is `CHARA.BIN`.
2. Labels were assigned by a loose "closest MDSP within 1.5MB" heuristic that mislabeled 60+ models.
3. Vertices are stored in **world space** (not bone-local); applying KMDs bind-pose matrices was inverse-transforming them into garbage space.
4. Tenchu uses an **X-up coordinate system** (X = vertical), so models loaded into Y-up viewers appear "lying on their side / fragmented".

**Fixes shipped:**
- New parser `kmds_parser.py` — 31-bone KMDs skeleton with parent table.
- New exporter `export_tenchu_models_v2.py` — reads CHARA.BIN, uses `chara_slot_map.json` for labels, rotates to Y-up.
- Re-extracted 70 models (37 character + 33 prop). Each model has `.obj` + `.skeleton.json` sidecar.
- Pruned 69 stale OBJ files from the old export.
- Rikimaru: 6,532 vertices, 3,745 faces, bbox 19×182×35 → proper humanoid silhouette.

**Verification:**
- All character models have bbox dimensions ~20 × ~180 × ~30 (humanoid).
- Lord Gohda is sitting (bbox 12×14×19, much shorter Y). Princess Kiku bbox 19×230×33 (taller, possibly with hat).
- All 31 bones parse with sensible world positions: root @ Y=108, arms @ ±77 X 140 Y, legs @ Y=-161.

**Remaining gap:** No textures yet (Tenchu TEX format is custom-swizzled PS2-style; deferred to later Day).
